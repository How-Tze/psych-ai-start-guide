## 读者与完成目标

第一类读者只用过豆包、千问或 DeepSeek 聊天，需要看到还能做什么，并找到可操作的起点。第二类已经读过主手册，希望照着做文献比较、设计材料、分析或写作。第三类已有跨文件和重复任务，需要代码助手、脚本或 API 的具体入口。

v0.12 完成时，第一类读者可以选一个可用产品、完成普通文本练习并保存结果；第二类可以跟着材料完成一条多步任务；第三类可以把同一项任务交给有文件执行能力的工具，打开实际产物并继续下一轮。

## 三条连续练习

**文献与设计：** 找到来源 → 读入三篇论文 → 回到原文定位 → 保存比较表和 Zotero 笔记 → 提出设计问题 → 检查已有短文、题目和条件列表。阅读页写产品操作；样本量、推断与设计理由回到主手册。任务完成应留下比较表及一项有理由的材料修订建议。

**结果与项目：** 读取确认结果表 → 起草数字段 → 将同表已有比较结果写入第二轮报告 → 保存当前项目说明 → 新对话接着修改 → 故意使用练习错误副本，再从正确输入恢复。报告生成与重新分析要分清：主手册两轮报告读取同一张已计算表，不得写成第二次拟合模型。

**质性阅读：** 提供六段合成访谈 → 定位原话 → 比较两种读法 → 用反例修改解释 → 保存阅读记录与后续问题。保留两名虚构说话者与六个片段的层次，不能写成六名受访者；与 API 分类演示分开解释用途。

数据教程保留六行数据的快速练习，进阶链接到主手册分析运行包。六行练习、24 行问卷、60 人纵向数据是不同教学输入，页面须明确说明，不能拼成同一份研究数据。

## 产品操作的取舍

千问、DeepSeek、ChatGPT、Claude、Gemini 在入口和任务选择中同等作为可选路线，按能力和读者所在地说明适用条件。豆包等熟悉的聊天入口可用于普通文本练习；具体能力同样须核查，不机械轮换品牌名字。

千问页先区分日常聊天、千问办公、Qwen Code；DeepSeek 页区分网页/App、桌面 Harness 和 API。产品速查负责解释入口；任务教程负责带读者完成工作。

每个核心任务选一条完整示范路线，最多补一条有实质差别的替代路线。教程合计至少包含国内、国际各一条完整示范；其余产品通过简短差异说明复用同一任务，避免复制多套长教程。

操作说明应覆盖：打开哪里、登录或安装需要什么、材料放哪里、发出什么要求、在哪里看/下载结果、怎样继续修改。按钮名称可配少量关键截图；没有账号条件时用官方文档支持的路线，明确标注核查方式，不编造实测经历。

研究设计和质性教程优先采用普通文本/文件对话。代码助手在可访问的环境内选择 Codex 或 Qwen Code 等正式支持的路线；DeepSeek Harness 目前属于预览入口，应保留状态说明，不将其设为新手必需步骤。
