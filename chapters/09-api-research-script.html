API 批处理：先用两条合成文本跑通

本练习演示：固定输入 → 调用模型 → 保存原始响应 → 检查格式 → 失败后继续。要求 Python 3.10+；没有编程环境可先完成普通文本练习。

输入八条虚构开放式回答，标签为学业压力、反刍、睡眠习惯、人际压力和其他。标签仅用于教学，不是经过验证的心理学编码。

第 1 步：取得完整示例

新建 api-batch 文件夹，把下面五个文件保存进去；保持文件名不变：

  • 输入 CSV
  • 主脚本 batch_label.py
  • 依赖 requirements.txt
  • 离线测试 test_batch_label.py
  • 操作与恢复说明 README

也可以从仓库选择 Code → Download ZIP，解压后进入 examples/api-batch。候选版尚未发布时，以本预览页的文件为准。

第 2 步：先离线检查

在这个文件夹打开终端：

python batch_label.py --dry-run
python -m unittest -v

Windows 已安装 Python 但没有 python 命令时可试 py。预检查应报告 8 行和最多调用 2 次；它不会请求 API。测试模拟成功与失败，不需要 Key。

第 3 步：决定是否实际调用

先阅读API 计费，在官方控制台创建自己的教学 Key。安装依赖：

python -m pip install -r requirements.txt

在 PowerShell 中隐藏输入 Key：

$demoSecureKey = Read-Host "DeepSeek API Key" -AsSecureString
$env:DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new("", $demoSecureKey).Password
python batch_label.py --max-calls 2
Remove-Item Env:DEEPSEEK_API_KEY

不要把 Key 粘进聊天或保存进脚本。命令至多发两次请求，没有自动重试；这只是数量上限，不是金额封顶。模型默认 deepseek-flash，入口来自 DeepSeek 官方文档，核查于 2026-10-13。

第 4 步：查看结果，而不是只看“成功”

打开 output/results.jsonl，每行是一条记录：

  • format_ok：JSON、标签和理由格式通过；
  • error：请求失败、返回被截断或格式不符合要求；
  • 原始输出与服务商响应保留在本地；
  • 每次运行单独保存模型、提示、输入摘要和参数。

即便 format_ok，也要对照原文判断标签。自动校验只能确认格式，没有证明标签的效度。

怎样继续、怎样恢复

相同输入、模型、提示和参数下，再运行会跳过已经格式通过的条目；错误条目可再次尝试。任一配置或输入改变会形成新批次，保守地重跑整份输入，旧记录继续保留。

例如前两条通过后重新运行，最多处理接下来的两条。超时可能已经产生服务端费用，重跑也可能再次收费。不要同时启动两个进程；强制中断后按 README 检查残留锁文件。

完成后保留输入、运行参数、原始响应、人工复核结论和真实控制台用量。本站此版本通过离线测试，未以真实 Key 发起付费调用。真实文本需另做伦理、隐私和编码方法判断。
