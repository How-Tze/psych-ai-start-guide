API 为什么这样计费：学会看价格表

第一次看到 API 价格表时，最容易困惑的是：为什么同一个模型会同时出现 Input、Output、Cached input、Batch，甚至搜索、代码执行等额外费用？

最基础的理解

大多数文本 API 都可以先用这个近似式理解：

费用 ≈ 输入 tokens × 输入单价 + 输出 tokens × 输出单价 + 额外工具费用

这里的 token 是模型处理文本的计量单位，不严格等于“一个汉字”或“一个单词”。你不需要先学会精确估算 token；更重要的是看懂账单由哪些部分组成。

为什么输入和输出价格不同

模型既要“读”你的输入，也要“生成”输出。很多服务商会给这两部分设置不同单价，因此长材料和长回答的成本结构也不同。

Cached input 是什么

当大量请求重复使用同一段提示、长文档或固定上下文时，一些服务商可以复用已经处理过的部分，并以更低价格计算。批量任务中保留稳定的提示与材料结构，也可能节省这部分成本。

Batch 又是什么

如果任务不要求立即返回，一些服务会提供批处理或异步接口，用较低价格换取更长等待时间。它适合大批量离线任务，不适合即时聊天。

Coding Plan 为什么看起来又不一样

有些厂商为代码助手提供订阅式套餐或专用额度。它与普通 API 可能使用不同的密钥（Key）、服务地址（Base URL）、模型范围和限额。

所以看到“月费 Coding Plan”时，不要默认它就是“API 包月”。

用一笔小账理解价格表

核查日期：2026-10-17。DeepSeek 官方价格表中，deepseek-flash 每百万未命中缓存输入 / 输出 tokens 的价格，空闲时段为 ¥1 / ¥4，高峰为 ¥2 / ¥8。北京时间周一至周五（中国法定节假日除外）9–12 点、14–18 点为高峰。

假设 1,000 次请求，每次 2,000 输入 tokens、500 个计费输出 tokens，全部输入未命中缓存：总量为 200 万输入、50 万输出。空闲价约为 2 × 1 + 0.5 × 4 = ¥4；高峰价约 ¥8。这是给定用量下的算例，不是实际任务报价；长上下文、推理输出、工具、重试都会影响账单。

当前 deepseek-flash 对应 DeepSeek-V4.1-Flash-1017。官方还说明 Search/Fetch 独立接口各按每 1,000 次成功请求 ¥5 计费；通过 Harness/Claude Code/Codex 使用 DeepSeek API 的服务端 Search/Fetch 调用，目前暂未收费，将于北京时间 2026-11-01 00:00 起按次收费。上述 ¥4/¥8 算例只含给定 tokens，未计搜索与抓取。

第一次只跑两条，再从服务商控制台查看真实用量并外推。产品订阅集中见预算页，本页维护 API 算例。

真正需要学会的是：

  1. 分清输入与输出；
  2. 看有没有缓存或批处理；
  3. 看额外工具是否单独收费；
  4. 确认当前使用的是按量 API，还是另一个订阅套餐；
  5. 正式项目用独立 Key 或项目标签追踪成本。

如果你只是偶尔调用插件，成本可能很低；如果是大规模 LLM simulation、长上下文或高价模型，成本可以迅速放大。API 的优势是可计量，不是天然便宜。
